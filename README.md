# skills-and-agents

A private archive of every agent skill and agent preset used on this machine:
the vendored upstream collections, the skills written for this project, the two
agent presets (`ctf-operator`, `laya-contributor`) and the generated Claude Code
subagent definitions. It exists so none of this work depends on an upstream
repository staying online, a branch not being rewritten, or a machine being
re-cloned.

**1,450 skill directories** — 1,138 vendored across ten upstream collections,
184 project-written `custom` skills, 106 installed without provenance metadata,
six locally authored skills (CTF/platform/tooling work), one Cloudflare skill,
and 15 skills carried by the two agent presets. 1,447 unique skill names, two
agent presets, 73 agent definitions (five Claude Code, 68 opencode) and the
bughunter round prompt; 9,176 files, ~102 MB packed.

The archive is **complete against the live catalog**: all 1,399 skills installed
at `~/.agents/skills` are represented, ten of them through recorded upstream
aliases (the installer renames a handful of skills). `tools/verify_archive.py`
proves this on demand.

## Layout

```
skills/
  <collection>/            ten vendored upstream repositories, verbatim (LICENSE kept)
  custom/                  184 skills written for this project (source_license: original)
  unattributed/            106 installed skills with no provenance metadata
  local-authored/          hackinghub, htb, mcpaudit-mcp-tool-audit, 3 hunt playbooks
  cloudflare_security-audit-skill/   one skill from cloudflare/security-audit-skill
agents/
  ctf-operator/            agent preset: 14 CTF skills, 8 tools, writeup pipeline
  laya-contributor/        agent preset: laya skill, 14 verification tools
  opencode/                68 opencode agent definitions (the bug-hunter roster) + README
  opencodex/               5 Claude Code subagent definitions generated by `ocx claude`
  hunt_prompt.md           the bughunter round prompt those agents are dispatched with
MANIFEST.json              machine-readable inventory (paths, SHA-256, aliases, counts)
SOURCES.md                 upstream URL, licence and skill count per directory
provenance/                installer manifest snapshot from 2026-09-10 (not a copy)
tools/
  build_manifest.py        regenerate MANIFEST.json from disk
  verify_archive.py        completeness + dedupe + provenance verification
```

## Using a skill

Each skill is a directory containing a `SKILL.md` with YAML front matter
(`name`, `description`). Point your agent framework's skill root at
`skills/<collection>/...` — the directory layout inside each vendored collection
is preserved, so upstream documentation about where skills live still applies.

```
find skills -name SKILL.md | wc -l
find skills -name SKILL.md | head
```

## Verification

```
python3 tools/verify_archive.py
```

The verifier checks eight things and exits non-zero if any fails:

1. `MANIFEST.json` matches every skill file on disk, byte-for-byte.
2. No two skills in the archive have identical bodies (no duplicates).
3. The only duplicate *names* are the three documented upstream collisions
   (`offensive-osint`, `osint`, `transilience-report-style`), recorded with
   paths and reasons in `MANIFEST.json`.
4. Every skill in the live catalog `~/.agents/skills` is represented, by name or
   through a recorded alias.
5. Every live agent preset in `~/.dsh/.agent-presets/` is archived file-for-file.
6. Every Claude Code subagent definition in `~/.claude/agents/` is archived
   byte-for-byte.
7. Every opencode agent definition in `~/.config/opencode/agent/` is archived
   byte-for-byte.
8. The bughunter round prompt is archived byte-for-byte.

Checks 4–8 are skipped with a warning when the live paths are absent (for
example on another machine); checks 1–3 always run. Override the live paths with
`--catalog`, `--presets`, `--claude-agents` and `--opencode-agents`.

A warning is expected for 19 skills whose installed copy is older than the
vendored upstream revision archived here (for example the six `hunt-*` skills
that moved since the September install). The archive keeps the newer upstream
revision deliberately; the older installed body is not duplicated.

Regenerate the inventory after any change:

```
python3 tools/build_manifest.py && python3 tools/verify_archive.py
```

## Duplicates, aliases and collisions

Every skill is stored once. Where the installer had flattened a vendored skill
under a new name (`bountyforge`, `bug-reaper`, `techstack-*`,
`trc-transilience-report-style`, `cmk-exploit-file-download`), the archive keeps
the upstream copy and records the alias in `MANIFEST.json` instead of storing a
second copy of the same body. Upstream itself ships three genuine name
collisions with different content; they are kept and documented rather than
silently dropped.
